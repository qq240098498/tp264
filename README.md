# 污染源在线监测与排污总量核算台

运维与环保岗共用的核算台：录排污单位与排放口、管在线设备、盯小时值、算日平均与总量、对许可量、出报表。

## 运行

```
npm install
npm start
```

默认端口 5264（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：单位数量与生产中数量、排放口数量与运行中数量、设备数量与各状态台数、监测数据条数与自动与补录条数、无效标记条数、报表数量与已上报数量、超标排放口数量、年累计排放量与年许可量对照；下面按排放口一行给出本月各指标的月均值、月总量与超标情况。
- **排污单位与排放口**：单位台账（编码、名称、行业、状态、许可证号、许可年起始日）带排放口清单；排放口台账（编码、名称、所属单位、类型、状态、设备数、数据条数），两者都带增改删。
- **在线设备**：设备台账（编号、所属排放口、监测指标、型号、设备状态、校准有效期、数据条数、无效标记条数），带增改删。
- **监测数据**：小时值清单（排放口、设备、指标、时刻、数值、标记、来源、登记人、是否计入、折算后浓度、当时氧含量与流量），支持按排放口、设备、指标、日期与月份筛选，带单条新增、修改与删除。
- **核算与报表**：选定排放口与月份后给出逐日明细（有效小时数、补录小时数、日均浓度、限值、是否超标、当日流量合计）与汇总（月均、月总量、季度总量、季度许可量、年累计、年许可量、超标天数与超标小时数、超标判定），并可生成与查看报表（草稿、已上报、退回）。
- **归档管理**：按许可年或按月归档。先「运行检查清单」（该时段数据是否齐全、有没有未处理的无效应答、报表是否都已上报），清单结果与当时口径版本一起定格进归档记录；确认后归档，该时段监测数据与报表进入只读（监测数据页显示「已归档/只读」锁标，接口返回 `ARCHIVED_READ_ONLY`，明确提示而不是静默失败），查询与统计照常可用。确需修改走「申请解档」（必填原因、影响范围、审批人），解档期间的每次增改删都留痕；改完「重新归档」，版本往前推一格（v1→v2→…），版本历史、解档记录、修改留痕、每版清单与口径快照都可在归档详情里查。

## 口径（页面上的说明与数字都要与本段一致）

1. **有效小时值**：数据标记为有效、设备状态为「正常」、数值在量程（默认 0 到 500）之内，三条都满足才计入统计；设备处于校准、维护、故障状态，或者数值超量程或为负数的，按无效处理（不计入平均、总量与超标判定），页面要显式标出来。
2. **折算浓度**：`折算浓度 = 实测浓度 × (21 − 基准氧含量) / (21 − 实测氧含量)`，基准氧含量默认 8（可在设置里改）；该时刻没有氧含量读数时按基准氧处理（等价于不折算）。所有平均、总量与超标判定都用折算后的浓度。
3. **日平均**：按小时流量加权，`日均 = Σ(折算浓度 × 该小时流量) / Σ该小时流量`；单日有效小时不足（口径按 18 小时）或者补录小时超过上限（默认 6 小时）的，**该日不计入平均与总量**，页面要写明原因。
4. **补录**：允许用相邻有效值补算缺失小时，补录数据要在页面与结果里与原数据区分开；补录超过单日上限时该日按无效处理，不许把补出来的数当真实监测结果用。
5. **月总量**：`每小时排放量(吨) = 折算浓度(mg/L) × 流量(m³/h) × 1000(升每立方米) / 1e9`，月总量是逐小时按时刻配对累加（浓度与流量必须取同一时刻的那一对）；月平均按有数据且有效的天数平均（分母是有效天数，不是当月天数）。季度总量与年累计用同一套公式逐小时累加，不做任何按天外推。
6. **季度与年**：季度总量按季度内逐小时累加；季度许可量按年许可量乘以该季度实际天数占全年天数的比例分解；年累计按许可年（单位台账里的许可年起始日）累计，跨自然年不重置也不带入其他许可年的数据。
7. **超标判定**：日平均超过限值（COD 100、氨氮 15，可改）**或者**小时值超过限值达到 3 次及以上，都算这个月超标；两项都要在页面上分别给出。
8. **不计入统计的情形**：排污单位处于停产状态、或者排放口处于停用状态的时段，其小时值不计入平均与总量，也不参与超标判定（但要保留可查）。

## 归档规矩

1. **归档粒度**：按月（`YYYY-MM`，当月 1 日到月末）或按许可年（取设置里许可年起始日的月-日，到下一年起始日前一天）。时段相互重叠的归档不能重复建立。
2. **归档前检查清单**（三项，结果连同生成时刻一起保存）：
   - 该时段数据是否齐全——在产单位的运行排放口每一天都应有读数（停产单位、停用排放口不要求），列出每个排放口缺数天数与日期；
   - 有没有未处理的无效应答——标记「无效」且未填处理说明（备注）的条数必须为 0；
   - 报表是否都已上报——该时段有数据的在产单位，每个月都要有「已上报」报表，草稿、退回、未建报表都算未完成。
   清单未通过默认不能归档；确认知情后可强制归档，归档记录里保留「强制归档」标记与当时清单。
3. **口径版本**：设置（核算口径）每被实质修改一次，`criteriaVersion` 加一并记入历史；每次归档/重新归档都把当时的口径版本与完整设置快照定格到该版本。
4. **归档后只读**：已归档时段的监测数据不能新增、修改、删除（含把别的时段数据改入该时段），该期间报表不能改状态/备注/新建；页面显示锁标并禁用入口，接口返回 HTTP 409 `ARCHIVED_READ_ONLY`，消息里点明所属归档时段与版本。查询、逐日明细、月/季/年统计一律照常。
5. **解档与留痕**：解档必须填写原因、影响范围、审批人。解档窗口内对监测数据/报表的每一次增改删都写入该归档记录的留痕（时刻、对象、改前→改后、操作人）。
6. **重新归档**：修改完成后重新跑检查清单并归档，归档版本 `version` 加一（v1→v2…），闭合本次解档窗口（记录起止与改动条数）。历史版本链、每版清单与口径快照、历次解档与全部留痕都可在归档详情中查看。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/plants | 单位清单（支持 status、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/plants/:id | 详情（含排放口、报表）/ 修改 / 删除 |
| GET / POST | /api/outlets | 排放口清单（支持 plantId、status）/ 新增 |
| PATCH / DELETE | /api/outlets/:id | 修改 / 删除 |
| GET | /api/outlets/:id/summary?month= | 月均、月总量、季度总量与许可、年累计、超标情况、设备清单 |
| GET | /api/outlets/:id/daily?month=&metric= | 逐日明细（有效小时数、补录小时数、日均、限值、是否超标、流量合计） |
| GET | /api/outlets/:id/exceedance?month=&metric= | 超标判定（超标天数、超标小时数、是否超标、月均） |
| GET / POST | /api/devices | 设备清单（支持 outletId、metric、status）/ 新增 |
| PATCH / DELETE | /api/devices/:id | 修改 / 删除 |
| GET / POST | /api/readings | 小时值清单（支持 outletId、deviceId、metric、day、month、limit）/ 新增 |
| PATCH / DELETE | /api/readings/:id | 修改 / 删除 |
| GET / POST | /api/reports | 报表清单 / 新建（归档期间返回 ARCHIVED_READ_ONLY） |
| GET / PATCH | /api/reports/:id | 报表详情（含各排放口的汇总与逐日明细）/ 改状态（归档期间只读） |
| GET | /api/archives | 归档台账（含当前口径版本 criteriaVersion） |
| GET | /api/archives/checklist | 归档前检查清单（scope=month&period=YYYY-MM 或 scope=permitYear&year=YYYY） |
| POST | /api/archives | 归档（清单未过需 force=true；保存清单、口径快照、v1） |
| GET | /api/archives/:id | 归档详情：版本历史、解档记录、修改留痕、各版清单与口径快照 |
| POST | /api/archives/:id/unarchive | 解档（必填 reason、impactScope、approver） |
| POST | /api/archives/:id/rearchive | 重新归档（清单复跑，版本 +1，闭合解档窗口） |

监测数据/报表的清单与详情里带 `archived`（已归档时段及版本）、`archiveOpen`（解档中时段）、`readOnly` 字段。已归档时段写操作返回 `409 ARCHIVED_READ_ONLY`；清单未通过返回 `422 ARCHIVE_CHECKLIST_FAILED`（`details.checklist` 带回清单）；时段重叠返回 `409 ARCHIVE_EXISTS`/`ARCHIVE_OPEN`。

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
